## 註解

**原則：說明「作用」，不逐行複述程式碼。**

### 類別與函式上方：一到三行說明作用

講清楚這東西負責什麼、有什麼不直觀的保證或限制。**設計理由不寫在這裡**，放 `docs/architecture.md`，註解留一個指標：

```
/** 依會話分配單調遞增序號。設計理由見 docs/architecture.md 決策 2。 */
```

### 函式內部：只在演算法或非直觀處理時簡述

一般的賦值、呼叫、判斷不加註解。**命名做不到的事才交給註解。**

### 並列的常數與值域：逐行註解，不省

**這是「不逐行註解」的例外，而且是硬性要求。** enum、權限位元、代碼欄位的值域、成組的設定常數 —— 每一項都要有自己的註解。

理由：這種宣告的語意不在程式碼裡。`type = 3` 本身什麼都沒說，讀的人得去翻 schema 或文件。**這裡的註解是把散落在別處的語意帶到眼前。**

- **寫名字沒說到的事**：什麼時候用、跟誰互斥、單位、為什麼是這個值、為什麼保留。把識別碼翻成中文再唸一次等於沒寫
- **行尾註解對齊成一欄** —— 這種宣告是拿來掃的
- 值不可重排的宣告（存進資料庫或協定的數字），在上方補一句「數字不可重排」

### 一律不要寫

- 複述程式碼的註解（`// 遞增 count`）
- 被註解掉的舊程式碼 —— 版本控制記著，刪掉
- 不附條件的 `TODO`。要寫就寫清楚：`// TODO(Phase 4): 上線事件通知後改為事件驅動`

## 錯誤處理

{{選定一種錯誤表達方式並寫死，例如「一律用 exception，配統一的轉譯層」或「一律回傳 Result」。混用是最糟的。}}

### 業務程式碼只管表達失敗，不自己組錯誤回應

錯誤轉成 HTTP 狀態碼、錯誤 JSON、協定錯誤訊息，**集中在傳輸層的一個轉譯點**。
領域層的錯誤型別**不依賴傳輸層的型別**（不 import HTTP 狀態碼或協定產生碼）。

能用語言特性讓「新增錯誤型別卻忘了對應」編譯失敗的，就用（例如 sealed class + 窮舉 `when`）。

### 錯誤訊息的分寸

錯誤訊息進日誌，**不原樣回給客戶端**。訊息要含足以除錯的識別碼；給客戶端的文字由轉譯層決定，**不包含 SQL、堆疊、內部路徑**。

### 不要吞掉錯誤

空的 catch、吞掉又回傳 null —— 都不可以。真的可以忽略時，**寫註解說明為什麼可以忽略**，並記一條 WARN。
包裝錯誤時**永遠保留原因（cause）**。

## 日誌

用參數化的寫法，不要字串串接（沒開的層級也會付串接成本）。

### 層級的判準是「量級」

| 層級 | 用途 | 量級 |
|---|---|---|
| `ERROR` | 需要人介入 | 應該極少 |
| `WARN` | 異常但已自動處理 | 每分鐘個位數 |
| `INFO` | 重要狀態變化（啟動、設定載入） | 每分鐘個位數 |
| `DEBUG` | 每個請求、每條連線、每則訊息 | 只在除錯時開 |

**每個請求或每則訊息等級的事件不進 INFO。** 用目標規模算一次：{{目標規模}} × 頻率 = 每秒幾條。

### 絕不記錄的東西

- 密碼、token、API secret、私鑰
- 含簽章的完整 URL
- 使用者的內容本體（訊息、檔案內容）與個資 —— 除錯時記長度與型別
- {{本專案特有的}}

## 秘密

- **秘密絕不進指令列參數。** 指令字串會出現在 process 列表、shell 歷史、遠端 ssh 的日誌裡。用檔案或環境變數傳
- 秘密檔案不進版控（`.env` 在 `.gitignore`）
- 診斷工具（profiler、crash dump）可能錄下環境變數，開之前確認

## 資料庫 migration（有用的話）

- **已 commit 的 migration 不可修改**，要改就新增下一號。改動已套用過的檔案會讓既有環境啟動失敗
- 例外是「還沒上線、可以整個重建」的初始 schema —— **那是使用者的決定**：直接改之前先問，報告裡寫明要重建哪些庫、會清掉什麼資料。第一次上線後這個例外關掉
- 時間欄位帶時區；布林欄位給預設值、不允許三態；非顯而易見的欄位加註解
- {{本專案的命名與慣例}}

## 協定與 API 合約（有多個客戶端的話）

**改協定定義是架構改動，依 `CLAUDE.md` 要先報告。**

| 可以 | 不可以 |
|---|---|
| 加新欄位、新的選項分支、新的 enum 值 | 改既有欄位的編號、型別、意義 |
| | 刪掉欄位後重用它的編號或名字 |

理由：**已安裝的舊版客戶端無法強迫立刻升級。**

產生碼不進版控、不手改；改來源定義後重跑 codegen。
