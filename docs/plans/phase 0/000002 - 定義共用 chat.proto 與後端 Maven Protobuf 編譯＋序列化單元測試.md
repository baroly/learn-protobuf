## 零、先定 2 個結構問題

### 1. ★ `proto/chat.proto` 的結構與 `java_multiple_files = true`

- **問題**：Protobuf 編譯成 Java 時，預設會把所有 `message` 與 `enum` 全部塞進同一個巨大的外部類別（例如 `ChatProto.ChatMessage`、`ChatProto.MessageType`）作為 static inner class；還是要拆成各自獨立的 `.java` 檔？
- **選擇**：在 `chat.proto` 設定 `option java_multiple_files = true;`，並定義 1 個枚舉（`MessageType`）與 2 個訊息結構（`ChatMessage`、`ChatHistoryResponse`）。
- **為什麼**：開啟 `java_multiple_files = true` 後，`ChatMessage` 與 `MessageType` 都是頂層類別（`import com.example.chat.proto.ChatMessage;`），在 Spring Controller 與 Service 中引用最自然，不會到處都是冗長的 `ChatProto.ChatMessage`。
- **連帶影響**：之後 Phase 1、Phase 2 後端所有程式碼都直接 `import com.example.chat.proto.*` 頂層類別。

### 2. Maven 自動編譯外層目錄 `../proto` 的方式

- **問題**：Maven 標準預設只看 `backend/src/main/proto`，但我們的 `.proto` 放在根目錄的 `proto/`（對 `backend/` 而言是 `../proto`），如何讓 Maven 每次編譯時自動去外層讀取？
- **選擇**：使用 `com.github.os72:protoc-jar-maven-plugin` 綁定在 Maven 的 `generate-sources` 階段，並將 `<inputDirectories>` 指向 `${project.basedir}/../proto`。
- **為什麼**：只要執行 `mvn compile` 或 `mvn test`（或在 IDEA 點擊 Reload Maven Project），就會自動觸發 `generate-sources`，把產生的 `.java` 放進 `backend/target/generated-sources/` 並自動掛載進編譯路徑。

## 三、替代方案與取捨

### A. `option java_multiple_files = true`（★ 建議） vs `false`（預設單一外部類別）

- **方案甲（★ 建議：`true`）**：每個 `message` / `enum` 各自生成獨立的 `.java` 檔（如 `ChatMessage.java`），程式碼乾淨易讀。
- **方案乙（`false`）**：全部塞在 `ChatProto.java` 裡面變成 `ChatProto.ChatMessage`。排除理由：當未來 `.proto` 訊息變多時，單一檔案會膨脹到數萬行，且 import 語句不直觀。

### B. 時間戳型別使用 `int64 timestamp`（★ 建議） vs `google.protobuf.Timestamp`

- **方案甲（★ 建議：`int64 timestamp` 存 Unix epoch 毫秒數）**：
  - 在 Java 端直接對應 `long` (`System.currentTimeMillis()`)，在前端 JS 直接對應毫秒數字（`Date.now()` / `new Date(Number(ts))`），零轉換成本。
- **方案乙（使用官方 Well-Known Type `google.protobuf.Timestamp`）**：
  - 內部拆成 `seconds` (`int64`) 與 `nanos` (`int32`) 兩個欄位。排除理由：前後端每次讀寫都要多寫一層 `{ seconds, nanos }` 與 `Instant` / `Date` 的轉換工具函式，對毫秒級聊天室屬於過度設計。

### 📚 必讀教學：本報告引入的 2 個核心套件詳解

在動手寫程式碼前，先認識我們在後端處理 Protobuf 必備的兩個套件：

#### 套件 1：`com.google.protobuf:protobuf-java`（Google 官方 Protobuf Java 執行期核心庫）
@but
下面 `허용` 語言用錯了

- **套件定位**：
  由 `protoc` 編譯器從 `.proto` 產生出來的 `.java` 檔案，本身只包含欄位的結構定義，它們底層繼承自 `com.google.protobuf.GeneratedMessageV3`（或 4.x 的 `GeneratedMessage`），並依賴這個套件提供的 `CodedOutputStream`（二進位編碼器）與 `CodedInputStream`（二進位解碼器）來完成真正的序列化工作。
- **常用功能與 API（必學！）**：
  1. **`Xxx.newBuilder()`（建立物件的唯一入口）**：
     Protobuf 產生的 Java 類別（如 `ChatMessage`）**沒有 public 建構子，也沒有 `setter`**！你必須呼叫靜態方法 `ChatMessage.newBuilder()` 取得 `Builder`，用鏈式呼叫 `.setId("1").setSender("Alice")` 設定欄位，最後呼叫 `.build()` 產出不可變（Immutable）的 `ChatMessage` 實例。
  2. **`message.toByteArray()`（序列化為二進位）**：
     將 `ChatMessage` 物件壓縮編碼成標準的 Protobuf `byte[]` 二進位陣列，可直接寫入 HTTP Body、WebSocket Frame、檔案或 Redis。
  3. **`Xxx.parseFrom(byte[] data)`（從二進位反序列化）**：
     接收 `byte[]`（也支援 `InputStream` 或 `ByteBuffer`），解析並還原為 `ChatMessage` 物件。若傳入損毀或非法的 byte 陣列，會拋出 `InvalidProtocolBufferException`（繼承自 `IOException`）。
  4. **`message.toBuilder()`（基於現有物件修改）**：
     因為 `ChatMessage` 是不可變的，當後端收到前端傳來的 `ChatMessage`（還沒填伺服器端 `id` 與 `timestamp`）時，不能直接 `msg.setId(...)`，而是呼叫 `msg.toBuilder().setId("101").setTimestamp(now).build()` 產生一個補齊欄位的新實例。
  5. **Repeated（陣列）欄位的 Builder API**：
     在 `ChatHistoryResponse` 中，`repeated ChatMessage messages = 1;` 會生成：
     - `builder.addMessages(ChatMessage)`：加入單筆訊息
     - `builder.addAllMessages(Iterable<ChatMessage>)`：一次加入整個 `List<ChatMessage>`
     - `response.getMessagesList()`：取得不可變的 `List<ChatMessage>`
     - `response.getMessagesCount()`：取得筆數
- **應該記住的要點（地雷與特性）**：
  1. **不可變性（Immutability）**：Build 出來的 `ChatMessage` 100% 執行緒安全，可以直接放進多執行緒共享的 `ConcurrentLinkedDeque` 中，不用擔心被其他執行緒偷改欄位。
  2. **`proto3` 預設不 허용 `null`**：呼叫 `builder.setSender(null)` 會直接拋出 `NullPointerException`！如果某個字串欄位沒填，它的預設值是空字串 `""`（數字預設是 `0`，enum 預設是編號 `0` 的值）。
  3. **預設值不佔傳輸空間（Default Value Omission）**：在 `proto3` 中，如果一個欄位的值剛好等於預設值（例如 `type = MessageType.CHAT (0)` 或 `timestamp = 0`），`toByteArray()` **根本不會把這個欄位寫進 `byte[]` 裡**，藉此極致壓縮封包大小；反序列化時沒讀到該欄位就會自動給預設值。

---

#### 套件 2：`com.github.os72:protoc-jar-maven-plugin`（Maven 自動編譯 `.proto` 插件）

- **套件定位**：
  它是一個開發期建置插件（不會打包進最終的應用程式 JAR）。它的任務是在 Maven 編譯 Java 程式碼之前，自動幫你去下載對應作業系統（如 Windows x86_64）的 `protoc` 編譯器執行檔，將 `.proto` 轉成 `.java` 原始碼。
- **常用配置參數**：
  - `<protocArtifact>com.google.protobuf:protoc:3.25.5</protocArtifact>`：指定要下載哪個版本的官方 `protoc` 編譯器（需與 `protobuf-java` 版本一致）。
  - `<inputDirectories>`：指定 `.proto` 檔案放在哪個資料夾。
  - `<outputTargets>`：指定要產出哪種語言（預設 `java`，並自動將產出目錄註冊進 Maven 的 compile source roots）。
- **應該記住的要點**：
  - **產出位置**：預設產在 `backend/target/generated-sources/`。**千萬不要手動去修改裡面的 `.java` 檔**，因為每次執行 `mvn clean compile` 都會被重新覆蓋。
  - **版本對齊**：`protobuf-java` 依賴庫的版本號（我們選用穩定且廣泛相容於 Spring Boot 3.4 的 `3.25.5`）必須與 `<protocArtifact>` 的版本號一致，避免產生碼呼叫到舊版沒有的 runtime 方法。

#### 步驟 1：建立 `proto/chat.proto`

在專案根目錄下建立 `proto` 資料夾，並在裡面建立 `chat.proto`：

```protobuf
// 指定使用 proto3 語法（目前的主流標準，語法精簡且預設省略零值欄位）
syntax = "proto3";

// Protobuf 命名空間（避免跨檔案訊息名稱衝突，前端也會以此作為命名空間）
package chat;

// === Java 程式碼生成專屬選項 ===
option java_package = "com.example.chat.proto";
option java_outer_classname = "ChatProto";
option java_multiple_files = true;

// 訊息類型枚舉（數字會直接寫入二進位封包，一旦定案不可重排）
enum MessageType {
  CHAT = 0;   // 一般使用者發送的聊天文字訊息（proto3 規定第一個枚舉值必須為 0 作為預設值）
  JOIN = 1;   // 使用者進入聊天室時的系統廣播通知
  LEAVE = 2;  // 使用者離開聊天室時的系統廣播通知
}

// 單筆聊天訊息結構（欄位編號 1~5 一旦定案不可重排或更改型別）
message ChatMessage {
  string id = 1;          // 訊息唯一識別碼（由後端伺服器統一產生）
  string sender = 2;      // 發送者暱稱
  string content = 3;     // 訊息文字內容
  int64 timestamp = 4;    // 發送時間戳（Unix Epoch 毫秒數，對應 Java long）
  MessageType type = 5;   // 訊息類型（預設為 CHAT = 0）
}

// 歷史訊息列表回應（Protobuf 頂層必須是 message，因此用 repeated 包裝多筆訊息）
message ChatHistoryResponse {
  repeated ChatMessage messages = 1;  // 聊天訊息清單（在 Java 對應 List<ChatMessage>）
}
```

#### 步驟 3：建立序列化單元測試 `ChatProtoSerializationTest.java`

在 `backend/src/test/java/com/example/chat/proto/ChatProtoSerializationTest.java` 建立以下測試類別，親手體驗 Protobuf 的 3 個核心特性：

```java
package com.example.chat.proto;

import com.google.protobuf.InvalidProtocolBufferException;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

import java.nio.charset.StandardCharsets;
import java.util.Arrays;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

/**
 * 驗證 ChatMessage 與 ChatHistoryResponse 的 Protobuf 二進位序列化契約。
 * 見 docs/plans/000002 第四節。
 */
class ChatProtoSerializationTest {

    @Test
    @DisplayName("1. 單筆訊息序列化為 byte[] 後反序列化，所有欄位應完全一致，且體積小於對等 JSON")
    void shouldSerializeAndDeserializeChatMessage() throws InvalidProtocolBufferException {
        // 1. 使用 Builder 建立不可變的 ChatMessage 物件
        long now = 1760590000000L;
        ChatMessage original = ChatMessage.newBuilder()
                .setId("msg-001")
                .setSender("Alice")
                .setContent("Hello Protobuf! 你好！")
                .setTimestamp(now)
                .setType(MessageType.JOIN)
                .build();

        // 2. 序列化成二進位 byte[]
        byte[] binaryBytes = original.toByteArray();

        // 對照組：如果用 JSON 表示完全相同的資料
        String equivalentJson = String.format(
                "{\"id\":\"%s\",\"sender\":\"%s\",\"content\":\"%s\",\"timestamp\":%d,\"type\":\"%s\"}",
                original.getId(), original.getSender(), original.getContent(),
                original.getTimestamp(), original.getType().name()
        );
        byte[] jsonBytes = equivalentJson.getBytes(StandardCharsets.UTF_8);

        System.out.println("=== Protobuf vs JSON 體積對比 ===");
        System.out.println("Protobuf bytes 長度 : " + binaryBytes.length + " bytes");
        System.out.println("Protobuf bytes 內容 : " + Arrays.toString(binaryBytes));
        System.out.println("JSON bytes 長度     : " + jsonBytes.length + " bytes");
        System.out.println("JSON 字串內容       : " + equivalentJson);

        // 驗證二進位體積確實比 JSON 更小
        assertThat(binaryBytes.length).isLessThan(jsonBytes.length);

        // 3. 從 byte[] 反序列化還原為新的 ChatMessage 物件
        ChatMessage parsed = ChatMessage.parseFrom(binaryBytes);

        // 4. 驗證每個欄位都精確還原
        assertThat(parsed).isEqualTo(original);
        assertThat(parsed.getId()).isEqualTo("msg-001");
        assertThat(parsed.getSender()).isEqualTo("Alice");
        assertThat(parsed.getContent()).isEqualTo("Hello Protobuf! 你好！");
        assertThat(parsed.getTimestamp()).isEqualTo(now);
        assertThat(parsed.getType()).isEqualTo(MessageType.JOIN);
    }

    @Test
    @DisplayName("2. 使用 toBuilder() 修改不可變物件，以及使用 ChatHistoryResponse 包裝多筆訊息")
    void shouldModifyViaToBuilderAndPackRepeatedMessages() throws InvalidProtocolBufferException {
        // 模擬前端只傳來 sender 與 content（未帶 id 與 timestamp）
        ChatMessage fromClient = ChatMessage.newBuilder()
                .setSender("Bob")
                .setContent("第一則訊息")
                .build();

        // proto3 未設定的欄位會自動取得預設值（空字串、0、編號 0 的 CHAT）
        assertThat(fromClient.getId()).isEmpty();
        assertThat(fromClient.getTimestamp()).isZero();
        assertThat(fromClient.getType()).isEqualTo(MessageType.CHAT);

        // 後端使用 toBuilder() 補上伺服器分配的 id 與 timestamp（原物件 fromClient 不會被改變）
        ChatMessage enriched = fromClient.toBuilder()
                .setId("server-1")
                .setTimestamp(1760590005000L)
                .build();

        assertThat(fromClient.getId()).isEmpty();
        assertThat(enriched.getId()).isEqualTo("server-1");

        // 將多筆訊息放入 ChatHistoryResponse (repeated 欄位)
        ChatHistoryResponse history = ChatHistoryResponse.newBuilder()
                .addMessages(enriched)
                .addMessages(enriched.toBuilder().setId("server-2").setContent("第二則訊息").build())
                .build();

        // 序列化並反序列化整個列表回應
        byte[] historyBytes = history.toByteArray();
        ChatHistoryResponse parsedHistory = ChatHistoryResponse.parseFrom(historyBytes);

        assertThat(parsedHistory.getMessagesCount()).isEqualTo(2);
        assertThat(parsedHistory.getMessagesList().get(0).getContent()).isEqualTo("第一則訊息");
        assertThat(parsedHistory.getMessagesList().get(1).getContent()).isEqualTo("第二則訊息");
    }

    @Test
    @DisplayName("3. 解析損毀或非法的二進位資料時，應拋出 InvalidProtocolBufferException")
    void shouldThrowExceptionWhenParsingCorruptedBytes() {
        // 構造一段不合法的 Varint / Wire Type 二進位資料
        byte[] corruptedBytes = new byte[]{(byte) 0xFF, (byte) 0xFF, (byte) 0xFF, (byte) 0xFF, (byte) 0xFF};

        assertThatThrownBy(() -> ChatMessage.parseFrom(corruptedBytes))
                .isInstanceOf(InvalidProtocolBufferException.class);
    }
```
