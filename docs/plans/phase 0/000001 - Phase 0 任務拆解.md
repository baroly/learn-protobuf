# 000001 - Phase 0 任務拆解

**狀態**：已完成（2026-10-16）：拆為 `000002`、`000003` 兩份報告，定案使用 JDK 21
**日期**：2026-10-16
**前置**：`docs/architecture.md` 已核准（2026-10-16）。

這份是 **Phase 0（地基：`.proto` 定義、前後端專案骨架與自動 Codegen、Java 序列化單元測試）** 的規劃型報告。它本身不寫任何程式碼，核准的是「**Phase 0 怎麼切成兩份實作報告、為什麼這樣切、以及前後端共用詞彙與目錄約定**」。

做完 Phase 0 之後：
1. 根目錄有前後端共用的 `proto/chat.proto`。
2. 在 `backend/` 執行 `mvn test`，Maven 會自動將 `chat.proto` 編譯成 Java 類別，並跑過一個 JUnit 5 單元測試 —— 親眼看到一個 `ChatMessage` 物件被序列化成 `byte[]` 再反序列化回來，且控制台會印出 **Protobuf 二進位大小 vs JSON 字串大小** 的實際數字對比。
3. 在 `frontend/` 執行 `npm run proto` 與 `npm run build`，Vite + Vue 3 + TypeScript 前端能自動從同一份 `chat.proto` 產出 `src/proto/chat.js` 與 `src/proto/chat.d.ts`，並通過編譯期型別檢查。

## 先對詞彙

這個階段會建立貫穿整個專案的核心名詞，在 `.proto`、Java 後端、Vue 前端中的對應關係如下：

| 概念 | `proto/chat.proto` | Java 後端 (`com.example.chat.proto`) | Vue 前端 (`src/proto/chat`) |
|---|---|---|---|
| 訊息類型枚舉 | `enum MessageType` (`CHAT=0`, `JOIN=1`, `LEAVE=2`) | `MessageType.CHAT` 等 | `chat.MessageType.CHAT` 等 |
| 單筆聊天訊息 | `message ChatMessage` | `ChatMessage`（不可變類別）與 `ChatMessage.Builder` | `chat.ChatMessage` 與 `chat.IChatMessage`（TS 介面） |
| 歷史訊息列表封包 | `message ChatHistoryResponse` (`repeated ChatMessage messages = 1`) | `ChatHistoryResponse` | `chat.ChatHistoryResponse` |

## 二、對既有功能的衝擊與破壞性風險

- **沒有衝擊**：目前尚無任何產品程式碼，Phase 0 為全新建立。
- **已知風險**：
  1. JDK 版本已由使用者定案於 IDEA 選用 **JDK 21**，消除了原本 JDK 26 的潛在相容性風險（若於外部終端機執行 `mvn`，需確保 `JAVA_HOME` 指向 JDK 21 或設定 `<java.version>21</java.version>`）。
  2. Vite 預設使用 ES Module (`import`)，而 `pbjs -t static-module` 預設輸出 CommonJS wrapper —— 將在 `000003` 中配置 `-w es6` 參數並以 `npm run build` 實測驗證。

## 三、替代方案與取捨

### A. 拆成 2 份報告：後端與前端分開（★ 建議） vs 合成 1 份大報告一次做完

- **方案甲（★ 建議：拆成 `000002` 後端＋Proto 與 `000003` 前端兩份）**：
  - **優點**：每一份只接觸一種語言與一套工具鏈（`000002` 專心學 `.proto` 語法、`protobuf-java`、`protoc-jar-maven-plugin`；`000003` 專心學 `protobufjs`、`pbjs`/`pbts`）。因為是由你親手寫程式，分兩步走負擔小、焦點清晰，且每一步都有獨立可跑的驗證指令。
  - **代價**：多寫與多核准一份報告。
- **方案乙（合成 1 份報告同時建好 `proto/`、`backend/`、`frontend/`）**：
  - **為什麼排除**：一次塞入 Maven 插件、Java Builder API、Vite 初始化與 `pbjs` CLI 四種新東西，報告太長且除錯時前後端混在一起。

### B. 目錄結構：Monorepo 三平級目錄 `proto/` + `backend/` + `frontend/`（★ 建議） vs `.proto` 放在 `backend/src/main/proto/`

- **方案甲（★ 建議：根目錄下 `proto/`、`backend/`、`frontend/` 平級）**：
  - **優點**：清楚體現「`.proto` 是獨立於前後端之外的通訊契約」，前端 `npm run proto` 與後端 `mvn compile` 各自往上讀 `../proto/chat.proto`，地位對等。
- **方案乙（`.proto` 塞在 `backend/src/main/proto/`）**：
  - **為什麼排除**：會讓前端腳本必須跨進後端深層目錄（`../backend/src/main/proto`）取檔，語意上像是前端依附於後端內部實作。
